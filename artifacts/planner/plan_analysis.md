# ProjectAI 기획 부합 평가 및 종합 분석

## 1. 기획 부합 여부 평가
- **최근 작업 요약**: 코드 무한 리뷰-수정 루프 종료, 정적 검증 통과, `NetPlayerMovement` 클라이언트 권한/물리 충돌 에러 방지(조기 반환) 적용 완료.
- **평가**: 최근 구현된 네트워크 오브젝트 풀, 스킬/애니메이션 서버 동기화(RPC), 권한 기반의 이동 처리 구조는 기획 문서(`plans\mvp plan.md`)가 요구하는 **"NGO 기반 호스트-클라이언트 구조에서의 안정적인 4인 멀티플레이 전투"** 기반에 완벽히 부합함. 
- 클라이언트 조작과 물리 에러를 서버/오너 권한(`IsServer`, `IsOwner`)을 명확히 하여 차단한 것은 마일스톤 1주차 목표인 '네트워크 기반 플레이어 행동 동기화'의 안정성을 높인 훌륭한 설계임.

## 2. 기획 요약
- **목표**: 최대 4인 호스트-클라이언트 환경에서 플레이어(마법)와 소환수(빛가루)가 적(기억의 파편충)과 자동으로 전투하는 루프 구현.
- **방향성**: 조작은 단순하게, 소환수가 알아서 적을 추적하여 싸우는 "소환술사"의 느낌을 주는 것이 핵심.
- **구조**: 방 입장 -> 전투 -> 클리어 -> 보상 획득 -> 포탈 이동의 로그라이크 형태 방 진행 로직.

## 3. 핵심 루프
1. **스폰**: 방 단위로 적(기억의 파편충) 스폰 (서버).
2. **전투**: 소환수 자동 추적 공격 및 플레이어 기본 마법 지원 (스킬 & 투사체 동기화).
3. **클리어**: 몹 전멸 시 클리어 상태 전환 및 파편(재화) 획득.
4. **보상 및 이동**: 보상 선택 후 다음 방으로 이동(포탈 동기화).

## 4. 필요한 시스템 (현재 상태 진단)
- **네트워크 풀링/스폰**: `NetworkObjectPool`, `NetMonsterSpawner` (구현 완료, MVP 부합)
- **스킬 및 애니메이션**: `BasicAttackLogic`, `EntityAnimator` RPC 기반 키프레임 동기화 (구현 완료)
- **이동 및 물리**: `NetPlayerMovement` 권한 기반 분리 및 조기 반환 (안정화 완료)
- **포탈 및 방 이동**: `NetLocationTeleportPortal` (구조 개편 진행 중, 3주차 목표)
- **AI 추적/전투**: 소환수와 몬스터의 근접 타겟팅 및 상태 머신 동기화 (검토 및 점검 필요)
- **보상 시스템**: 개별 3택 UI 및 스탯(`NetStatComponent`) 연동 (향후 구현 필요)

## 5. MVP 범위 (Scope) 유지 권고
- 새로운 스킬이나 소환수/적의 종류를 늘리지 말고 **기존에 명시된 단일 클래스(마법 1종, 빛가루 1종, 파편충 1종)의 상호작용** 완성에 집중해야 함.
- 네트워크 레이턴시가 발생해도 "애니메이션"과 "투사체/데미지 처리"가 자연스럽게 보이는지 검증하는 것이 최우선임.
- 최종 보스는 몬스터 웨이브 형태로 스케일을 줄이는 것이 마일스톤 기한 내 달성에 유리함.

## 6. 향후 작업 순서 (마일스톤 2~3주차 대응)
1. **AI 전투 동기화 (Week 2)**: 
   - 기억의 파편충과 빛가루의 NavMesh 기반 네트워크 이동 최적화 확인.
   - 타겟팅 갱신 및 근접 공격 스킬이 서버에서 정상 처리되어 데미지가 깎이는지 PlayMode 테스트.
2. **방 진행 시스템 연동 (Week 3)**:
   - 몹 전멸 시 포탈이 열리도록 스포너와 포탈의 상호작용(Event) 연결.
3. **보상 및 스탯 처리 (Week 3)**:
   - `NetStatComponent` 기반 보상 획득 시 최대 체력/공격력 등 즉시 증가 로직 구현.
   - 클라이언트별 개별 보상 선택 UI 및 서버 확정 로직.

## 7. 주의할 점 (설계 조언)
- **이동 처리(Jitter 현상 주의)**: `NetPlayerMovement`에서 조기 반환(Early Return)을 적용했으므로, 권한이 없는 클라이언트 화면에서 위치 보간(Interpolation)이 튀는 현상이 없는지 실제 환경(또는 시뮬레이터)에서 시각적 확인이 필요함.
- **애니메이션 상태 전환**: 스킬 강제 캔슬이나 피격 시 애니메이션 Transition이 네트워크 딜레이와 맞물려 굳어버리는 버그를 지속 방어해야 함 (현재 `OnAnimationStateExited`를 통한 초기화 방어는 훌륭함).
- **포탈 동기화**: 4인이 동시에 포탈을 탈 때, 서버 텔레포트 명령과 클라이언트 카메라 및 씬 전환이 엉키지 않도록 `NetLocationTeleportPortal`의 예외 처리를 엄격히 할 것.

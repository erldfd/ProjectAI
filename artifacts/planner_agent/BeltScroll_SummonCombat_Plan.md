# 벨트스크롤 소환수 전투 구현 계획 (MVP)

## 1. 기획 요약
*   `GDD_SummonCombat.md`의 소환수 전술(타겟 마킹, 명령 토글, 패턴 방패막이 등)을 2.5D 벨트스크롤 환경에 통합.
*   Z축(깊이)을 활용하여 적을 둘러싸거나, 소환수 뒤에 숨어(Bodyblocking) 적의 공격을 피하는 전략적 포지셔닝 강조.
*   논리적 3D 좌표와 화면 상의 2D 렌더링 좌표를 나누는 **축분리**를 핵심 기반으로 사용.

## 2. 핵심 루프
1.  **위치 선정**: 플레이어와 소환수가 X, Z축 이동을 통해 적의 사각지대나 유리한 깊이로 이동.
2.  **전투 및 마킹**: 동일한 깊이(Z축 오차 범위 내)의 적에게 공격 시도, 플레이어 타격 시 타겟 마킹 부여.
3.  **소환수 연계**: 소환수가 마킹 대상을 일점사하거나 호위 태세로 전환하여 방패막이 역할 수행.
4.  **회피 기믹**: 적 광역기 패턴 발생 시, 회피 동기화(Dodge Sync) 혹은 Z축 이탈을 통한 생존.

## 3. 필요한 시스템
*   **축분리 시스템 (Axis Separation)**: 로직 상의 3D(X, Y, Z) 위치를 관리하고, 렌더링용 2D(X, Y) 좌표로 변환.
*   **동적 렌더링 정렬 시스템**: Z축 좌표를 기준으로 `SpriteRenderer`의 `SortingOrder`를 매 프레임 갱신 (깊이판정).
*   **깊이 기반 충돌 판정 (2.5D Hitbox)**: Y축(높이)과 Z축(깊이) 오차 한계치 내에서만 유효 타격으로 인정.
*   **NGO 멀티플레이 동기화**: 렌더 변환 전의 **논리 좌표(로직 3D 위치)만 동기화**하여 클라이언트 단에서 각각 렌더 처리.
*   **소환수 커맨드/AI 시스템**: 타겟 마킹 인식 및 호위/공격 태세 전환 로직.

## 4. MVP 범위
*   논리 좌표 기반 이동 및 2D 렌더링 축분리 적용.
*   Z축 기반 동적 렌더링 정렬 (앞뒤 가림 처리).
*   깊이(Z축)가 일치해야 타격되는 기본 전투 판정 시스템.
*   가까운 적 우선 공격 및 플레이어 타겟 마킹을 최우선하는 소환수 AI.

## 5. 작업 순서 (우선순위 제안)
> **Q) 깊이판정을 먼저 구현해야 할까요?**
> **A) 아니오. "축분리"가 최우선입니다.**
> 깊이판정(동적 렌더링 정렬)은 정렬의 기준이 되는 Z축 데이터가 존재해야 가능합니다. 로직 상의 깊이를 정의하는 축분리 시스템이 선행되어야 합니다.

*   **Step 1. 축분리 시스템 기반 공사**: 캐릭터 구조를 `Logic`과 `View(Render)` 객체로 분리. `Vector3` 이동 로직 적용.
*   **Step 2. 동적 렌더링 정렬 (깊이판정 포함)**: 분리된 로직의 Z축 값을 뷰로 가져와 `SortingOrder` 실시간 갱신 적용.
*   **Step 3. 깊이 기반 충돌 판정**: 단순 `Collider2D` 겹침이 아닌 Z축 오차(Tolerance)를 체크하는 Hit/Hurtbox 시스템 연동.
*   **Step 4. 소환수 AI 및 네트워크 연동**: NGO `NetworkTransform` 커스텀으로 로직 좌표 동기화, `GDD_SummonCombat`의 마킹 시스템 구현.

## 6. 주의할 점
*   **네트워크 동기화 대상**: 반드시 화면의 시각적 2D 위치가 아닌, **논리적 3D 위치를 동기화**해야 클라이언트간 해상도나 화면 비율 차이에서 발생하는 위치 어긋남을 막을 수 있음.
*   **몬스터 광역기 설계**: Z축과 무관하게 화면 전역을 덮는 장판형 광역기인지, 특정 Z축 깊이 범위에만 영향을 주는 광역기인지 기획적 분리 및 충돌 로직 처리가 필요함.
